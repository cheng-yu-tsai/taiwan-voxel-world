- **做法：** 對 3 秒 `requestAnimationFrame` 樣本計算中位數、nearest-rank P95 和最長間隔，與平均 FPS 一起顯示並加入可複製報告；統計抽成無副作用函式，明確驗證空樣本、單筆樣本及非有限／負值。
- **原因：** 平均 FPS 可能掩蓋少量長時間卡頓；P95 和最大間隔可為後續桌機／手機比較提供分布資訊。
- **可重用範圍：** 瀏覽器遊戲或動畫原型比較相同場景的更新排程；在平均速率旁回報尾端延遲，避免只用平均數掩蓋不穩定時段。
- **注意事項：** 量到的是 `requestAnimationFrame` 呼叫間距，不是 GPU 完成時間或端到端輸入延遲；背景分頁略過結果，跨裝置比較時要記錄視窗、像素比例和瀏覽器環境。
- **驗證：** 新增統計函式測試涵蓋空／單樣本、偶數中位數、P95、最大值、輸入不變及無效值；全套 39 項 Node 測試、JavaScript 語法與差異空白檢查通過。尚未在瀏覽器量測實際 FPS 或卡頓數值。

## 2026-11-26｜讓遊戲對話框保留鍵盤焦點

- **做法：** 一律從開啟的視窗內列出可見、可操作的連結與表單控制項；Tab 從最後一項循環到第一項，Shift+Tab 從第一項回到最後一項。開啟時記住觸發元素，關閉或按 Esc 時還原；一般視窗互相切換時保留最初的頁面觸發元素。
- **原因：** 僅設定 `aria-modal` 不會自動攔截鍵盤焦點；焦點跑到遮罩後的遊戲操作時，鍵盤使用者可能無法理解目前所在視窗或在其中操作。
- **可重用範圍：** 單頁遊戲和設定頁的 modal／alertdialog；用同一個可見控制項查找與焦點返回流程，可讓多種視窗遵循一致操作方式。
- **注意事項：** 動態視窗需在顯示後再查詢可見控制項；隱藏檔案輸入等不可操作元素應排除。關閉視窗後的回焦點目標若即將隱藏，應改回到仍可見的頁面控制項。
- **驗證：** 對照開場、交通、設定、說明及確認視窗的互動路徑；全套 35 項 Node 測試、JavaScript 語法、HTML ID 與可存取名稱標記檢查、`git diff --check` 通過。瀏覽器目視操作仍受本工作階段的瀏覽器控制通道限制。

## 2026-11-26｜以遊戲內確認視窗處理覆寫操作

- **做法：** 將匯入世界與重設世界的原生 `window.confirm` 改成共用遊戲內確認對話框；以 `textContent` 放入標題與訊息，對話框預設聚焦取消，支援取消／確認按鈕、Esc、點擊遮罩取消、Tab 焦點循環和關閉後還原焦點。危險操作的確認按鈕採獨立樣式，匯入訊息列出方塊數並明示完整取代。
- **原因：** 原生確認視窗會暫停頁面互動，瀏覽器自動化不一定能處理它，也不便統一鍵盤焦點和遊戲視覺。
- **可重用範圍：** 純前端應用中的重設、匯入或覆寫確認；以 Promise 回傳使用者選擇，並集中管理焦點、Escape 與取消狀態，可避免每個危險按鈕各自實作不一致的確認流程。
- **注意事項：** 確認取消、按 Esc、點擊遮罩和其他關閉方式都要 resolve 為 `false`，避免呼叫端等待不完；不可只用顏色表示危險，按鈕文字應指出具體結果。測試原生對話框時需要瀏覽器對話框處理器；遊戲內對話框可用一般鍵盤和 DOM 流程驗證。
- **驗證：** 全套 35 項 Node 測試通過；JavaScript 模組語法、HTML 唯一 ID、確認按鈕與標題／描述關聯及 `git diff --check` 通過。此工作階段的瀏覽器控制通道無法開啟本機或公開量測頁，故未做互動目視驗證；效能量測待辦仍保持未完成。

## 2026-11-26｜補齊觸控建造操作

- **做法：** 以 `pointer: coarse` 顯示觸控控制，沿用 Pointer Events 讓移動和跳躍可按住，並在 `pointerup`、`pointercancel` 與 `lostpointercapture` 時釋放；挖掘與放置則用可鍵盤啟動的按鈕 `click`，共用既有準星互動邏輯。
- **原因：** 原型已有觸控移動和拖曳轉向，但觸控玩家無法跳躍、挖掘或放置，建造循環因此中斷。
- **可重用範圍：** 第一人稱瀏覽器沙盒或類似的觸控遊戲；持續輸入（移動／跳躍）使用按住與釋放，單次行動（挖掘／放置）使用按鈕點擊，並依粗指標提供至少 44 CSS px 的觸控目標。
- **注意事項：** 移動按鈕必須在取消與失去指標捕捉時清除按鍵狀態，避免手指移出按鈕後角色持續移動；單次行動沿用相機準星，才會與桌面端的指向規則一致。
- **驗證：** 以 390×844、粗指標瀏覽器檢查，七個按鈕均為 46×46 CSS px，頁面沒有水平溢出；點擊挖掘和放置後方塊數依序由 5,115 降到 5,114、再回到 5,115。
- **測試限制：** 測試後以遊戲的「重設這個世界」清除測試改動時，原生 `window.confirm` 對話框使瀏覽器自動化輸入逾時，還原步驟未完成；遇到原生確認框時須用可接收瀏覽器對話框的測試控制方式，或人工完成確認。

## 2026-11-26｜讓各島地形更容易辨認

- **結果：** 保留台灣本島山脈與澎湖低平地勢，新增金門緩丘、馬祖岩脊、綠島中央火山高地、蘭嶼南北雙峰；設定檔和地形函式用 Node 測試覆蓋，函式行、分支與函式覆蓋率均為 100%。

- **存檔注意：** 存檔保存完整方塊地圖，沒有記錄哪些方塊來自地形生成；更新地形時保留舊存檔，除非設計出不遺失玩家挖掘／建造的遷移方式，否則不要自動重設或提高存檔版本。

## 2026-11-26｜用區塊索引縮小局部重建範圍

- **做法：** 用 `ChunkBlockIndex` 維護每個水平區塊所含的方塊 key；世界載入／重設後重建索引，放置和挖掘時同步更新，渲染重建只走該區塊的 key 集合。
- **原因：** 原本每次重建區塊都掃描整個方塊 Map；世界變大後，即使只挖一格，也會重複檢查其他島嶼和遠方區塊的方塊。
- **可重用範圍：** 以空間分塊、局部編輯為主的 voxel 世界；每個索引必須在初始生成、讀檔、重設、放置和刪除路徑同步更新，並以 `Math.floor` 算負座標的區塊，避免零點兩側分區錯誤。
- **驗證：** 14 項地形與索引測試通過；索引、地形與設定模組覆蓋率均為 100%。

- **可重用範圍：** 已有鍵盤修飾鍵加速邏輯的瀏覽器遊戲；觸控端可用持續按住的虛擬按鈕映射同一輸入狀態，不重複實作移動規則。
- **注意事項：** 按鈕使用 pointerup、pointercancel 和 lostpointercapture 清除 Shift 狀態；CSS 觸控目標尺寸設定為 46 CSS px，仍需在實際手機上檢視位置和手感。
- **驗證：** 全套 32 項 Node 測試、語法檢查及差異空白檢查通過；尚未進行手機實機操作測試。

## 2026-11-26｜先定技術升級門檻，再擴大原型

- **做法：** 將技術文件分成已存在的架構、分階段建議、效能量測方法和尚未驗證的目標；目前保留 Three.js 靜態原型，列出 GLB 素材、固定壓力情境和 localStorage 升級 IndexedDB 的條件。

- **可重用範圍：** 早期瀏覽器遊戲或互動原型的技術規劃；把現況、目標和決策門檻分開，可讓後續改架構有可核對的原因。

## 2026-11-26｜建立可在不同裝置重跑的效能量測頁

- **做法：** 新增開發用瀏覽器頁，量測初始世界生成（三次中位數）、單區塊網格重建、5,000／選擇性 20,000 分散方塊、2,000 單區塊方塊及 3 秒畫面更新；頁面直接建立記憶體測試世界，不呼叫遊戲存檔或編輯方法。
- **原因：** 技術路線要求先有同場景桌機／手機數據，再決定是否調整分塊、載入或素材流程；缺少工具時容易把單次主觀感受當成效能瓶頸。
- **可重用範圍：** 小型 Three.js／WebGL 原型的可重複手動基準；匯出裝置、瀏覽器和場景數據，方便對照不同裝置，而不需要測試帳號或碰觸玩家存檔。
